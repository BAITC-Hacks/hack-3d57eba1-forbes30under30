## 1. Кейс

Трек: Гос. услуги
Кейс: «Аким на 5 часов» — AI-симулятор управления городом
Данные: `data/districts.json`, `data/measures.json` (синтетический датасет организаторов, переведён в JSON)

## 2. Проблема

Кто: городской управленец или аналитик, распределяющий ограниченный бюджет.
Когда: при выборе программы развития нужно одновременно учесть 5 направлений,
взаимные эффекты мер, лаги, синергии и слабые районы. Вручную это не просчитать,
а «интуитивные» решения оставляют провалы (как Нура по соцсфере).
Цена: неверно распределённый бюджет = годы без эффекта для целых районов.

## 3. Решение в одном предложении

AI-симулятор, где детерминированный движок точно считает Astana Quality of Life Score
по правилам кейса, а AI-агент через инструменты анализирует набор решений, объясняет
компромиссы и предлагает конкретные улучшения, подтверждённые расчётом.

Ключевой принцип (из ТЗ кейса): LLM числа не считает и не придумывает.
Все числа — из движка. Агент получает результаты расчёта через tools.

## 4. Основной сценарий

Вход: пользователь выбирает ровно 5 мер из 14 (для районных — район), бюджет 100.
Шаги:
1. UI в реальном времени показывает бюджет, остаток, нарушения правил (валидатор).
2. «Рассчитать» → движок: новые показатели, D по районам, D_avg, min, N_crit, Score,
   вклад каждой меры, синергии.
3. Агент (LLM + tools): вызывает score, contributions, suggest_improvements,
   формирует объяснение: сильные стороны, риски, компромиссы, 2–3 улучшения с цифрами.
4. UI: Score с дельтой к базе 52.56, таблица районов до/после, лог шагов агента.
Выход: Score, разбор сценария, рекомендации. Сценарий можно сохранить и сравнить.

## 9. Стек

Node.js 20 LTS + TypeScript + Next.js (App Router, UI и API в одном процессе) | Tailwind | OpenAI SDK + function calling | zod | данные: JSON в `data/`, без БД

## 10. Архитектура

```
UI (Next.js page) → /api/analyze → Engine (pure TS: validate, score, contributions, optimizer)
                                  → Agent (OpenAI + tools → Engine) → объяснение + рекомендации
                    /api/scenarios → data/scenarios.json (сохранение и сравнение)
```

Движок полностью детерминирован и покрыт смоук-тестом на эталонных числах.
Агент — единственное место, где вызывается LLM. Tools агента = функции движка.

## 15. Вопросы жюри

- Чем это отличается от ChatGPT? — LLM не считает, все числа из движка, рекомендации проверены перебором.
- Что если модель ошибётся? — Она не может изменить числа, только текст; числа всегда показаны рядом.
- Как подключить реальные данные? — Заменить два JSON-файла, формулы параметризованы.
- Почему все меры уходят в Нуру? — Формула штрафует слабый район (30% на min и штрафы за <40), агент это объясняет.
- Масштабирование? — Другие города, больше районов, реальные стоимости, участие граждан.
