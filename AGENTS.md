# AGENTS.md — правила для AI-агента

## Контекст

Хакатон HackAlem AI, на разработку 5 часов. Проект будут запускать технические
эксперты по README без нашей помощи, поэтому надёжность запуска важнее
количества фич.

Проект: «Аким на 5 часов» — AI-симулятор управления городом для городского
управленца. Пользователь выбирает ровно 5 мер из 14 в рамках бюджета 100, движок
считает Astana Quality of Life Score по правилам кейса, AI-агент объясняет результат
и предлагает улучшения.
Основной сценарий: выбор 5 мер (с районами) → валидация и бюджет → расчёт Score,
показателей районов, вклада мер → агент через tools анализирует и объясняет →
UI показывает Score, дельту, таблицу районов, лог шагов агента, рекомендации.
Обязательные требования кейса: см. TZ.md, раздел 5. Правила расчёта: `data/measures.json`
(rules, synergies, incompatibilities) и раздел «Движок» ниже.

## Стек (фиксирован, не менять)

- Node.js 20 LTS, TypeScript (strict), npm
- Next.js 14+ (App Router): страницы — UI, `app/api/*` — backend. Один процесс, одна команда запуска
- `openai` — официальный SDK, ключ из `process.env.OPENAI_API_KEY`
- `zod` — валидация входа и структурированных ответов LLM
- Tailwind CSS — стили. Никаких UI-библиотек сверх этого без указания
- Данные: JSON/CSV в `data/`. Без базы данных, без ORM, без Docker, если не сказано иначе
- Тесты/скрипты запускаются через `tsx`

Не добавлять другие фреймворки, state-менеджеры, очереди, БД без явного указания.

## Команды

```bash
npm install          # установка
npm run dev          # запуск для разработки, http://localhost:3000
npm run build        # прод-сборка, должна проходить без ошибок
npm start            # прод-запуск
npm run smoke        # смоук-тест основного сценария на data/sample/
npm run typecheck    # tsc --noEmit
```

`npm run smoke` — это `tsx scripts/smoke.ts`: прогоняет основной сценарий от входа
до выхода на демо-данных и падает с ненулевым кодом, если результат не получен.

## Главные правила

1. **Одна задача = одна фича.** Делать ровно то, что просят. Не добавлять
   авторизацию, платежи, админки, БД, кэши и «на будущее».
2. **Запуск.** После каждой задачи должны проходить `npm run typecheck`,
   `npm run build` и `npm run smoke`. Если что-то сломалось — сначала починить.
3. **Секреты.** Только через переменные окружения. Никогда не писать ключи в код,
   конфиги, логи, тесты, README. Клиентские компоненты (`"use client"`) не должны
   обращаться к OpenAI напрямую — только через `app/api/*`. Новую переменную
   добавлять в `.env.example` с пустым значением и описанием.
4. **Ошибки.** Все внешние вызовы (LLM, API, файлы, сеть) обёрнуты в try/catch
   с понятным сообщением пользователю. Приложение не должно падать из-за пустого
   ключа, таймаута или плохого входа. API-роуты возвращают `{ error: string }`
   с корректным HTTP-статусом.
5. **Минимум зависимостей.** Не тянуть библиотеку ради одной функции.
   Версии фиксированы в `package.json` (без `^` для ключевых пакетов) и `package-lock.json`
   коммитится.
6. **Простота.** Никаких абстракций «на вырост». Плоская структура, понятные имена,
   короткие функции. Код должен читаться экспертом за 5 минут.
7. **TypeScript strict.** Без `any` без крайней необходимости. Типы ответов LLM
   описаны через zod-схемы и выводятся из них.
8. **Не переписывать работающее.** Если что-то работает — не рефакторить без просьбы.
9. **Не трогать без указания:** `.gitignore`, `.env.example`, `AGENTS.md`, `TZ.md`.

## Движок (lib/engine/) — главное правило проекта

LLM НИКОГДА не считает и не придумывает числа. Все числа — только из движка.

- `lib/engine/data.ts` — загрузка и типизация `data/districts.json`, `data/measures.json`.
- `lib/engine/validate.ts` — `validate(decisions)`: ровно 5 решений; без повторов;
  сумма стоимости ≤ 100; районная мера обязана иметь район, городская — не иметь;
  не более 2 мер одного направления; несовместимости (M1+M3 всегда; M4+M7 и M5+M13
  только в одном районе). Возвращает список причин на русском.
- `lib/engine/score.ts` — `score(decisions)`:
  1. realized = (8 − lag) / 8 для каждой меры; эффект районной меры — только её район,
     городской — все 5 районов.
  2. Синергии: если выбраны обе меры пары, фиксированный бонус (не масштабируется лагом)
     в район первой меры пары; если первая мера городская — во все районы.
  3. clip каждого показателя в [0, 100].
  4. D_d = Σ w_k × I'_dk; D_avg = Σ pop_d × D_d; N_crit = число пар (район, показатель) < 40.
  5. Score = 0.7 × D_avg + 0.3 × min(D_d) − 1.0 × N_crit.
  Возвращает: score, baseScore, delta, D по районам, D_avg, minDistrict, criticals
  (список пар), показатели до/после по районам, вклад каждой меры (score с мерой
  минус без неё), сработавшие синергии.
- `lib/engine/optimize.ts` — `suggestSwaps(decisions)`: перебирает замену одной меры
  (любая другая мера × любой район) и возвращает топ-5 валидных улучшений с дельтой;
  `bestOverall()`: полный перебор всех валидных наборов (≈694 395), результат
  кэшируется в `data/best.json` при первом вызове.
- Эталонные числа (обязательный смоук-тест): база 52.56; пример из ТЗ
  M7@nura, M8@nura, M10@nura, M12, M5@saryarka = 56.54 при стоимости 95;
  M9@nura, M11@nura, M10@nura, M12, M4@nura = 55.67; лучший известный набор
  M2, M3@nura, M8@nura, M9@nura, M14 = 57.24. Округление до 2 знаков.
- Движок — чистые функции без side effects, без зависимости от Next.js и OpenAI.

## Агентная логика

- Агент живёт в `lib/agent/`. Он сам выполняет шаги: вызывает инструменты,
  обрабатывает данные, принимает промежуточные решения. Не сводить всё к одному промпту.
- Инструменты агента — отдельные функции в `lib/agent/tools/`, каждая с zod-схемой
  входа и описанием. Использовать function calling / tools API OpenAI.
  Набор tools: `validate_set`, `score_set`, `get_contributions`, `suggest_swaps`,
  `compare_sets`, `get_district_profile`. Все они вызывают функции движка.
- Итоговый ответ агента — структурированный JSON (zod): summary, strengths[],
  risks[], tradeoffs[], recommendations[{change, expectedDelta, why}], нельзя
  включать числа, которых нет в результатах tools.
- Промпт агента прямо запрещает считать самому и требует ссылаться на числа из tools.
- Каждый шаг агента логировать в понятном виде (что делает, что получил) и
  отдавать в UI как «ход мыслей» — это нужно для демо и README.
- Ответы LLM, от которых зависит логика, запрашивать в структурированном виде
  (JSON) и валидировать zod-схемой. При невалидном ответе — один повтор, потом
  понятная ошибка.
- Все промпты хранить в `lib/agent/prompts.ts`, не размазывать по коду.
- Ставить таймаут на вызовы LLM (60 секунд) и показывать пользователю состояние ожидания.

1. `npm run typecheck` — без ошибок.
2. `npm run build` — без ошибок.
3. `npm run smoke` — основной сценарий проходит на `data/sample/`.
4. Убедиться, что в выводе нет трейсбеков и ключей.
5. Коротко написать, что сделано и как проверено.

## Коммиты и push (обязательно после каждой задачи)

Организаторы проверяют историю на GitHub каждый час. Локальный коммит не считается.
Поэтому после каждой завершённой задачи (и не реже чем раз в 30 минут работы) выполняй:

```bash
git add -A
git commit -m "<type>: <что сделано>"
git pull --rebase
git push
```

- Сообщения на английском: `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`, `test: ...`
- Перед началом любой задачи: `git pull --rebase`.
- Если `git pull --rebase` или `git push` дали конфликт или ошибку — НЕ решать
  самостоятельно, не делать `--force`, не сбрасывать историю. Остановиться и
  написать пользователю, что произошло.
- Коммитить только рабочее состояние: `npm run typecheck` и `npm run build` должны
  проходить перед коммитом. Если проверки падают, сначала починить.
- Никогда не коммитить: `.env`, `node_modules`, `.next`, логи, кэши, `data/uploads/`.
- Не менять git-конфигурацию (имя, почту, remote), не создавать новые ветки без указания.
  Работа ведётся в ветке `main`.

## Структура проекта

```
app/
  page.tsx              # главный экран: выбор 5 мер → расчёт → результат и разбор
  api/
    analyze/route.ts    # POST {decisions}: validate → score → agent → результат + лог шагов
    scenarios/route.ts  # GET/POST: сохранение и список сценариев (data/scenarios.json)
  layout.tsx
components/
  MeasurePicker.tsx     # каталог мер, выбор района, бюджет, живая валидация
  ScoreCard.tsx         # Score, дельта к базе, D_avg, min, N_crit
  DistrictTable.tsx     # показатели до/после по районам, подсветка < 40
  AgentReport.tsx       # разбор агента + лог шагов + рекомендации с кнопкой «Применить»
lib/
  engine/
    data.ts             # загрузка JSON и типы
    validate.ts         # правила набора
    score.ts            # расчёт Score и вкладов
    optimize.ts         # замены и полный перебор
  agent/
    index.ts            # оркестрация: tools loop с OpenAI
    prompts.ts          # системный промпт и шаблоны
    schemas.ts          # zod-схемы tools и итогового отчёта
    tools/              # по файлу на инструмент
  openai.ts             # клиент OpenAI, ключ из env, единая обработка ошибок
data/
  districts.json        # датасет районов (из ТЗ кейса)
  measures.json         # каталог мер, правила, синергии, эталонные числа
  scenarios.json        # сохранённые сценарии (создаётся при первом сохранении)
scripts/
  smoke.ts              # проверка движка на эталонных числах + один вызов агента
README.md
.env.example
.nvmrc                  # 20
```
